# Threat model

Protect endpoint credentials, enrollment authority, analyst sessions, event integrity, evidence availability and personal data. Trust boundaries are the Windows service identity, host network, ingest listener, analyst browser, database, release pipeline and optional inference process. The host administrator and central deployment administrator can subvert local controls. Preserve provenance and make the limits of single-host auditing visible.

| Threat | Design control | Verification and residual risk |
| --- | --- | --- |
| Forged endpoint or reused enrollment | Admin creates one-use, short-lived enrollment bound to an assigned endpoint. Agent generates key locally, submits CSR over validated TLS. Store token digest and consume atomically. Use distinct client certificates, renewal and immediate server-side disable by identity. | Race two registrations, substitute identity, expire and revoke a cert. Endpoint compromise still permits plausible fabricated telemetry under that identity. |
| Fabricated, replayed or missing evidence | Derive endpoint from authenticated identity. Track source, clock quality, sequence gaps, replay conflicts and independent corroboration. | Compare contradictory synthetic events. Display source claims separately from server observations and analyst conclusions. |
| Service overprivilege and secret disclosure | Dedicated service identity with explicitly tested Security channel read ACL. Restrict spool, key and configuration ACLs. Use encrypted host volumes, rotate keys, exclude command lines and raw XML by default. Linux uses a dedicated user with journal access. | Confirm access under the service account, deny writes to audit configuration and deny other local users spool access. Channel access itself can expose sensitive records. |
| Untrusted input or resource exhaustion | Bound body size, item count, field lengths, depth, per-agent rate, concurrency and database pool. Reject unsupported versions and encodings. Use parameterized SQL, escaped text rendering and bounded quarantine. | Boundary fixtures, malformed synthetic batches and fair-share tests. A valid noisy device may saturate its own quota. |
| Analyst privilege abuse | Browser uses OIDC authorization code flow with PKCE, validated issuer/audience/nonce/state, HTTP-only Secure session cookie, CSRF defense and server-enforced roles. Reader searches. Analyst updates incidents. Administrator enrolls and disables agents. | Deny every privileged route to lower roles. Check export and event detail permissions independently. |
| Database or signing-key compromise | Private database network, separate ingest/query/worker/migration roles. Protect CA and backups outside source control. Keep signing offline or in a managed signer. Restrict metrics to operators. | Restore encrypted backup on a clean host, review grants, rehearse credential rotation. A central administrator can alter local records. |
| History tampering and privacy | Append audit entries for enrollment, revocation, searches of sensitive detail, exports, role changes, incident edits and retention. Log actor, action, request ID, time and result without event bodies or tokens. Export to independently controlled storage for stronger integrity. | Test access restrictions, expiry and evidence markers. Backup expiry follows its documented retention cycle. |
| Compromised update or model | Pin dependencies, verify release signatures and digests before installation, publish provenance and rollback steps. Accept only trusted model artifacts with a verified digest. | Reject a modified package and exercise rollback. MVP uses administrator-installed updates. |
| Instructions embedded in telemetry | Treat event text as untrusted data, minimize fields, isolate model process, prohibit tools and validate evidence citations. | A synthetic event requesting an action produces no action or state change. Withhold unsupported summaries. |

Default pilot retention proposal: events and deduplication records 7 days, alert evidence summaries and audit history 90 days, encrypted backups 7 days. Apply deletion in bounded batches, record the last successful run and alert on backlog. Preserve minimum case metadata and expiry markers after source deletion. Never silently extend raw-event retention by copying full payloads into notes or summaries. Review policy with the deployment owner before collecting real data.
