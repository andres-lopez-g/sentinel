# Contributing

Phase 0 welcomes design review. Open an issue or pull request identifying the requirement, the failure case and a proposed acceptance test. Use synthetic records and reserved example addresses. Keep real endpoint logs, credentials and private infrastructure details out of public discussions.

The maintainer approves architecture, scope and the MVP acceptance matrix before application development begins. Later changes should link an issue, describe observable behavior and compatibility, and include the smallest test that demonstrates the change. Review Windows and Linux implications when altering shared contracts. The repository structure document defines tooling and CI conventions.

For a suspected security issue, use GitHub private vulnerability reporting if enabled, or request a private contact channel without publishing sensitive details.
